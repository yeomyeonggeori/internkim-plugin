# 견적서 (Quotation)

output: pdf
filename: 견적서_<수신처>_<YYYYMMDD>.pdf

## Purpose

거래처에 상품·서비스 가격을 제안하는 대외 문서. 부가가치세법상 세금계산서 기재사항(공급자·공급받는자·품목·공급가액·세액·작성일)에 준하는 정보를 갖춰야 실무에서 그대로 발주·계약 근거로 쓰인다. 수신처와 품목·금액이 확정 정보여야 한다.

## Required fields

- recipient: 수신처 회사명 필수, 담당자명은 있으면 함께. 공급받는자 사업자등록번호를 받았으면 회사명 다음 줄에 추가한다.
- 공급자 상세(사업자등록번호·업태·종목·대표자)는 별도 표를 만들지 않는다 — profile.legalAttributes가 letterhead에 이미 인쇄된다.
- meta: 합계금액(한글병기), 견적일자, 유효기간, 납기, 납품장소, 결제조건, 입금계좌(profile.bankAccount) — 전부 필수, 값이 없으면 요청자에게 확인
- items: 품명·규격·수량·단위·단가는 요청자 제공 값만 사용, 1행 이상
- items.totals: 공급가액 합계 → 부가세(10%) → 총 합계 순서
- notes: "아래와 같이 견적합니다."
- signature: 발행일 + "회사명 대표이사 대표자명", stamp true

## Fixed wording

- notes: "아래와 같이 견적합니다."
- footer: "본 견적은 견적일로부터 <N>일간 유효합니다." — meta의 유효기간과 N을 반드시 맞춘다.

## Density gate (deliver 전 자기검사)

- 합계금액 meta 행에 한글병기("일금 ○○○원整")와 아라비아 숫자(₩)가 둘 다 있는가?
- 품목표가 7열(품명·규격·수량·단위·단가·공급가액·세액)인가?
- 견적일자·유효기간·결제조건·입금계좌가 meta에 전부 있는가?
- notes에 "아래와 같이 견적합니다."가 있는가?
- signature에 stamp: true가 있는가?

## Rules

- 금액은 천단위 콤마, 합계 값에만 "원"을 붙인다. 부가세 별도·포함을 반드시 명시한다.
- 세액은 공급가액의 10%로 계산하고 합계가 행 합과 일치하는지 검산한다.
- 품명·단가·수량이 없으면 지어내지 말고 요청자에게 확인한다.
- title은 "견 적 서"처럼 글자 사이 공백을 넣는다.
